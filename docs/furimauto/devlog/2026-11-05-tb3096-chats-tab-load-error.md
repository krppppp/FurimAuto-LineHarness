# TB-3096 管理画面のタブ切り替えで「チャットの読み込みに失敗しました」（2026-11-05）

## なぜ
- くろさん 11/5 11:39（TB-1998）: 未読などのタブを押すと「チャットの読み込みに失敗しました。もう一度お試しください。」

## 確かめた事実
- 文言は `chats/page.tsx` の `loadChats` の catch だけ。`/api/chats` が 2xx 以外か、通信そのものが失敗したときに出る
- Cloudflare のゾーン集計（furimauto-line.t4-corp.com・/api/*・オリジン 5xx）: 10/28 以降は 2 回だけ
  - 11/5 11:08 `/api/chats/search` 500 ×5
  - 11/5 11:38 `/api/chats` 500 ×4（同じ分に 200 ×2）→ くろさんの 11:39 の報告と合う
- D1 の集計: 友だち一覧のタグ付け（`SELECT t.* FROM tags t INNER JOIN friend_tags …`）が 11/5 01:47 に 700 本、11:08 に 834 本、11:38 に 767 本。500 の 2 回はどちらもこれと同じ分
  - 出どころ: チャット画面が開くたびに呼ぶ `api.friends.list({ limit: '800' })`。Worker は友だち 1 人ごとに `getFriendTags` を `Promise.all` で同時に投げる。チャット画面はこの結果を新規メッセージ欄の名前・アイコンにしか使わず、タグは使っていない
- 再現（Bearer・読み取りのみ）: 友だち 800 件の取得中にタブの一覧を投げると 0.1 秒 → 3.3 秒に遅れる。500 は出なかった。取得そのものは 7.5 秒
- いまの本番は 全て・未読・対応中・解決済・🔥未対応のみ とも 200（Worker 直・Pages 経由とも）
- 11/4 には /api 全般でオリジン応答なしの 504 がまとまって出ている時間帯があるが、同じ分の Pages Functions・Worker の集計はすべて success。今回の 500 とは別もの（未確認）

## 原因
- 事実: 11:38 の失敗は Worker が返した 500
- 仮説: チャット画面を開いた直後の 800 本の同時クエリで D1 が詰まり、同時に投げたタブの一覧が 500 になった（同じ分に重なっていること・遅れが再現することまで確認）
- 未確認: 500 の本文（Workers Logs は wrangler の権限で読めない＝Forbidden。D1 の集計にも 11:38 の一覧クエリが残っていない）

## 直したこと
- `chats/page.tsx` の友だち一覧取得を `includeTags: false` に（b31190b）。表示に使う id・displayName・pictureUrl・isFollowing は変わらない。800 件の取得 7.5 秒 → 0.44 秒、D1 の同時クエリ 800 本 → 0
- 本番 Pages `2f4d8bdd`（b31190b）。戻し: Pages rollback で `fa3d75a7`（7cdf4a7）

## 事故
- 最初に af75c92 起点の a038d70 を出したところ、31 秒前に出ていた TB-3105（7cdf4a7「開いただけでは未読から外さない」）を約 1 分上書きした。rollback で戻し、7cdf4a7 の上に載せ直して出した
- 教訓: Pages を出す直前（ビルド後）に canonical_deployment を読み直し、起点がそれを含むか確かめる。9 時台に読んだ値で済ませない
