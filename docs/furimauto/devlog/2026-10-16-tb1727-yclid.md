# 2026-10-16 TB-1727 yclid を友だちまで保存する

## なぜ
LINEヤフー広告（検索・ディスプレイ）を立ち上げる（TB-1723）。LP は yclid を CTA の /auth/line・LIFF に載せるが、LineHarness は yclid を受け取る場所が無く、/auth/line・/r/:ref・LIFF クライアントのどこで落ちても ref_tracking に残らなかった。実登録を LINEヤフーにオフラインCV で戻すには、友だちと yclid のひも付けが要る。

## 何を
- migration `091_ref_tracking_yclid.sql`: `ref_tracking.yclid TEXT`
- `routes/liff.ts`: /auth/line（LIFF URL・OAuth state・QR）、/auth/oauth（state）、/auth/callback（state → ref_tracking・friends.metadata）、/api/liff/link（新規・既存の 2 分岐）に gbraid/wbraid と同じ形で yclid を追加
- `index.ts` /r/:ref の引き継ぎキー、`client/main.ts` の getAdParams に yclid
- `entry-routes.ts` の RefTracking 型と recordRefTracking の INSERT に yclid
- ref（ad_yahoo_search・ad_yahoo_display）は既存の仕組みのまま friends.ref_code と ref_tracking.ref_code に入る（entry_route が無くても保存される）

## 入れなかったもの
- `getRefTrackingWithClickIds`・`ad-conversion.ts`: yclid だけの行で Google/Meta の自動送信が走らないよう、条件に足していない
- ダッシュボードの CLICK_ID_COND・/r/ の hasClickId: 広告／自然の数え方が変わるので触っていない
- `bootstrap.sql`: 089 以降が生成されておらず、再生成すると無関係の差分が出るため触っていない

## 確認
- `packages/db/test/ref-tracking-yclid.test.ts`（4 件）: migration、/auth/line の LIFF URL と /auth/oauth の state、/api/liff/link で ad_yahoo_search・ad_yahoo_display と yclid が保存され Google 送信が走らないこと。liff.ts の変更を外すと 3 件落ちる
- apps/worker の vitest 1402 件すべて通る（変更前と同じ）。packages/db の 110 件の失敗は変更前から同じ（affiliate 系など）
- tsc（apps/worker）エラー無し
- dev D1（line-crm-rebase）に 091 を適用済み。dev D1 には 086（gbraid/wbraid）が入っていない
- 本番 D1 は読み取りのみ: yclid 列なし、Yahoo 流入の行は 0
